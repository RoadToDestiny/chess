# Chess Blunder Prediction (Прогнозирование шахматных ошибок)

Научно-исследовательский проект по теме:  
**«Прогнозирование вероятности шахматных ошибок на основе градиентного бустинга»**  
(Decision Trees with XGBoost & Automated Ground-Truth Labeling via Stockfish)

## 2. Часто задаваемые вопросы (Ответы на ключевые вопросы)

### В1: Запускалось ли обучение физически?
**Да, обучение моделей запускалось в реальности.**  
При выполнении команды `python scripts/run_pipeline.py`:
1. Модель градиентного бустинга `xgboost.XGBClassifier` была обучена на обучающей выборке (Train: 3 448 позиций) с ранней остановкой по валидационной выборке (Val: 716 позиций).
2. Классовый дисбаланс был автоматически скомпенсирован через параметр `scale_pos_weight` (доля ошибок в выборке составляет ~11.6%).
3. Обученная модель сохранена на диск в бинарном JSON-формате: `artifacts/models/model.json` с полным описанием метаданных признаков в `artifacts/models/model_metadata.json`.
4. Были рассчитаны метрики на тестовой выборке (Test: 728 позиций) и сгенерированы графики калибровки и важности признаков.

### В2: Как именно проводились эксперименты?
Все 3 эксперимента, зафиксированные в методологическом плане статьи, были выполнены:
- **Основной эксперимент:** проверка качества вероятностных прогнозов полной модели (ROC-AUC, PR-AUC, Brier Score), построение диаграммы надёжности (калибровки вероятностей) и расчёт важности признаков по Gain.
- **Эксперимент 1 (Проверка гипотезы H2):** сравнительное обучение двух моделей:
  - *Модель А:* только позиционные признаки (9 характеристик);
  - *Модель Б:* позиционные + метапризнаки игроков и контроля времени (14 характеристик).  
  Результат зафиксирован в `reports/tables/exp1_feature_comparison.csv`.
- **Эксперимент 2 (Проверка гипотезы H3):** анализ чувствительности модели к порогам ошибки 150, 200 и 300 сантипешек. Разметка пересчитывалась мгновенно по формуле без повторного запуска Stockfish, и для каждого порога оценивалось качество прогноза. Результат сохранён в `reports/tables/exp2_threshold_sensitivity.csv`.

### В3: На каких данных проводился контрольный запуск?
- Контрольный запуск проводился на **структурированном калибровочном датасете** (70 партий, 4 892 полухода), полностью сгенерированном по правилам шахмат и строго соответствующем контракту схемы (Data Contract).
- Это позволило подтвердить сквозную работоспособность архитектуры: отсутствие синтаксических ошибок, математическую корректность расчёта потерь, защиту от утечки данных (Group Split по `game_id`) и корректную генерацию всех артефактов без необходимости суточного ожидания вычислений Stockfish на терабайтах базы Lichess.

### В4: Как запустить обучение на реальной базе Lichess?
Для получения финальных результатов для публикации:
1. Скачайте PGN-файл партий Lichess (поддерживаются форматы `.pgn`, `.pgn.gz`, `.pgn.zst`) в папку `data/raw/` (например, `data/raw/lichess_games.pgn.zst`).
2. Установите Stockfish и укажите путь к бинарнику в `.env` (`STOCKFISH_PATH=/path/to/stockfish`).
3. Запустите фильтрацию партий по критериям ($\ge 10+0$, $Elo \ge 1600$):
   ```python
   from chess_error_prediction.data.game_filter import filter_pgn
   from pathlib import Path
   filter_pgn(Path("data/raw/lichess_games.pgn.zst"), Path("data/raw/filtered_games.pgn"))
   ```
4. Запустите пайплайн:
   ```bash
   python scripts/run_pipeline.py
   ```
   Скрипт автоматически обработает реальные партии, проведёт через Stockfish 17, обновит `final_dataset.csv`, обучит модели и перезапишет финальные таблицы и графики.

## 3. Выполненные задачи трёх бэкендеров (Этапы 1–11)

- **Бэкендер 1 (Stockfish и PGN):**
  - Разработан UCI-клиент `StockfishEngine` с контекстным менеджером и проверкой `verify()`.
  - Зафиксированы параметры движка: `Stockfish 17`, глубина 18 полуходов, `mate_score_cp = 100000`, оценки строго с точки зрения белых (White POV).
  - Реализовано потоковое чтение архивов Lichess (`.zst`, `.gz`, `.pgn`) и фильтрация по тайм-контролю ($\ge 10+0$) и рейтингам ($\ge 1600$).
  - Реализовано вычисление потери оценки с точки зрения игрока, делающего ход, и изоляция матовых позиций.
- **Бэкендер 2 (Метаданные, признаки и датасет):**
  - Реализован модуль извлечения признаков позиции до совершения хода (материальный баланс, фигуры, пешки, шахи, взятия, фигуры под боем, фаза партии, динамика оценки).
  - Реализовано извлечение метаданных игроков (`player_rating`, `opponent_rating`, `rating_diff`) и времени (`time_control_base`, `time_control_inc`).
  - Разработан модуль сборки итогового датасета `build_dataset.py`.
- **Бэкендер 3 (Машинное обучение, валидация и эксперименты):**
  - Разработана спецификация Data Contract (`schemas.py`) и аудит на утечку целевой информации (`check_for_target_leakage`).
  - Реализован детерминированный Group Split (70/15/15) строго по `game_id` с проверкой на нулевое пересечение партий.
  - Настроен пайплайн обучения XGBoost с ранней остановкой и динамическим расчётом `scale_pos_weight`.
  - Реализован расчёт метрик (ROC-AUC, PR-AUC, Brier score), построение диаграммы надёжности (калибровки) и графика важности признаков.
  - Реализованы сценарии проведения всех трёх научных экспериментов.
- **Совместно (Все бэкендеры):**
  - Подготовлен минимальный рабочий пример `scripts/mwe.py`.
  - Разработан бенчмарк замера времени обработки `scripts/benchmark_timing.py`.
  - Подготовлены черновики разделов научной статьи в `reports/paper/`.

## 4. Быстрый запуск

### 4.1. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 4.2. Запуск полного набора тестов (28 тестов)
```bash
python -m pytest tests -v
```

### 4.3. Запуск Минимального Рабочего Примера (MWE — Этап 4)
Демонстрация полного пути от PGN-партии до строки датасета:
```bash
python scripts/mwe.py
```

### 4.4. Замер времени обработки и бенчмарк (Этап 7)
```bash
python scripts/benchmark_timing.py
```

### 4.5. Запуск полного исследовательского пайплайна (Этапы 8–10)
```bash
python scripts/run_pipeline.py
```
